# 扫地机器人智能客服Agent 本地单机部署需求文档

## 文档说明

1. 适用场景：仅支持单机本地部署，不适配分布式架构、云端部署、多租户SaaS架构。

2. 环境约束：项目强制锁定运行环境为Python 3\.14\.6，采用uv作为唯一包管理工具；大模型服务依赖本地Docker容器部署的FreeLLMAPI常驻运行。

3. 地址规范：系统所有服务访问地址统一使用127\.0\.0\.1，规避本地域名解析异常问题。

4. 端口规划：本地服务端口固定分配，无自定义修改场景，FreeLLMAPI占用3001端口、FastAPI后端服务占用8000端口、Streamlit前端页面占用8501端口。

5. 文档用途：仅用于项目本地环境搭建、服务部署、功能调试，无冗余业务规划内容，可直接用于完整项目落地实施。

## 1 项目概述

### 1\.1 业务定位

本系统为扫地机器人专属本地智能客服系统，基于单机架构运行，为终端用户提供全场景智能问答服务，核心覆盖产品咨询、设备故障排查、日常保养指导、环境清扫适配判断、个性化清扫报告生成等功能。系统依托本地RAG向量知识库弥补传统客服知识滞后缺陷，通过ReAct智能体自主调用多类工具，自动拆解并解决用户复杂咨询问题。

系统核心能力由两大模块支撑：一是ReAct智能体引擎，通过思考、行动、观测循环逻辑，自主完成多工具调用与复杂问题求解；二是RAG检索增强模块，基于本地文档构建向量知识库，有效降低大模型输出幻觉，保障问答专业性与准确性。

### 1\.2 技术架构栈

|后端服务框架|FastAPI \+ LangChain \+ LangGraph|
|---|---|
|智能体运行模式|LangChain ReAct 循环推理模式|
|大模型服务网关|FreeLLMAPI（Docker本地容器、OpenAI接口兼容）|
|向量存储组件|Chroma 本地文件持久化向量数据库|
|文本处理组件|RecursiveCharacterTextSplitter 递归文本分片器|
|前端交互页面|Streamlit 轻量化Python Web页面|
|本地数据存储|SQLite 轻量本地数据库|
|环境依赖管理|uv（强制使用，锁定Python3\.14\.6版本）|
|日志处理机制|自定义分级、按天分割日志组件|

## 2 系统功能模块详情

### 2\.1 ReAct智能体核心引擎

1. 接口适配：对接本地FreeLLMAPI服务地址http://127\.0\.0\.1:3001/v1，兼容标准OpenAI接口协议，完成对话生成、文本向量嵌入两类核心请求。

2. 容错重试：内置模型自动路由与故障转移机制，单模型出现限流、5xx服务异常、请求超时问题时自动切换模型，单请求最大重试次数为20次。

3. 会话稳定性：设置模型会话粘性机制，同一会话30分钟内固定使用同一模型，避免上下文语义断裂。

4. 工具调度：支持@tool装饰器批量注册自定义工具，智能体可自主判断工具调用时机与调用顺序，支持串行、并行两种调用模式。

5. 流式输出：对话响应采用SSE流式协议，实现文字逐字实时输出，完整留存多轮对话上下文信息。

### 2\.2 RAG本地知识库模块

1. 文档适配：仅支持PDF、TXT格式文档上传导入，单文件最大容量50MB，支持单文件上传与批量增量导入。

2. 文本分片：采用递归分片策略，优先保留完整段落语义，超长段落自动拆分句子，支持自定义分片尺寸与重叠参数。

3. 向量生成：调用FreeLLMAPI向量嵌入接口，自动完成文档分片向量化处理，持久化存储至本地Chroma向量库。

4. 智能检索：默认检索知识库Top3高相似度文本片段，拼接参考内容生成专业问答结果。

5. 索引更新：文档新增、修改、删除后，系统自动触发向量索引重建，同步更新知识库版本信息。

### 2\.3 智能体内置工具集

系统内置多款自动化工具，由智能体根据用户问题自主触发调用，无需人工干预，具体能力如下：

1. 天气查询工具：获取指定城市或用户本地地理位置的温湿度、风力、空气质量数据，辅助判断清扫适配场景。

2. 位置获取工具：读取用户本地授权地理位置，未授权时提示用户手动输入城市信息。

3. 用户标识工具：获取当前会话唯一用户ID，用于关联设备历史使用数据。

4. 使用记录查询工具：根据用户ID与自定义时间范围，查询设备清扫时长、清扫面积、故障记录、耗材损耗数据。

5. 产品信息查询工具：检索扫地机器人机型参数、新旧版本差异、产品功能说明等资料。

6. 故障排查工具：基于用户故障描述或设备错误码，匹配知识库对应解决方案，完成故障答疑。

### 2\.4 清扫报告生成模块

1. 意图识别：精准识别用户“生成清扫报告”类指令，自动切换报告生成专属会话上下文。

2. 标准化输出：加载报告专属提示词，强制输出规范Markdown格式报告，统一内容排版。

3. 多源数据聚合：自动串联用户信息、设备清扫记录、环境天气数据，完成多维度数据整合分析。

4. 固定报告维度：报告包含设备使用概况、清扫数据统计、设备健康状态、耗材更换建议、季节清扫适配建议五大固定模块。

### 2\.5 会话与消息管理模块

1. 会话隔离：基于全局唯一thread\_id作为会话标识，实现多会话数据完全隔离，互不干扰。

2. 会话操作：支持用户新建、切换、清空、删除会话，适配多场景对话需求。

3. 数据持久化：所有会话信息、聊天消息永久存储至本地SQLite数据库，服务重启不丢失数据。

4. 异常兜底：FreeLLMAPI服务异常、工具调用失败、知识库无匹配内容时，系统输出友好提示信息，不展示底层代码报错堆栈，保障服务稳定性。

### 2\.6 前端交互模块

1. 页面布局：采用侧边栏\+主内容区经典布局，侧边栏展示会话列表，主内容区为聊天交互窗口，底部固定消息输入框。

2. 内容渲染：区分用户与AI助手消息样式，完整支持Markdown表格、文本、报告渲染展示。

3. 流式交互：适配SSE流式输出，实时渲染AI回复内容，展示加载状态指示器。

4. 会话缓存：基于页面缓存机制留存会话数据，页面刷新后不丢失当前对话。

5. 设备适配：页面自适应PC、移动端浏览器尺寸，兼容多终端访问。

## 3 系统接口规范

### 3\.1 通用接口约定

1. 接口前缀：所有业务接口统一前缀为/api/v1。

2. 数据格式：常规接口返回JSON格式数据，流式对话接口采用text/event\-stream（SSE）协议。

3. 状态码规范：200为请求成功、400为参数异常、404为资源不存在、500为服务内部异常。

### 3\.2 大模型服务接口规范

FreeLLMAPI本地服务基础地址：http://127\.0\.0\.1:3001/v1，统一采用Bearer鉴权方式，鉴权Token为freellmapi\-xxx（从容器后台仪表盘获取）。

|接口请求路径|接口功能说明|
|---|---|
|POST /v1/chat/completions|实现对话生成，支持流式输出与工具调用能力|
|POST /v1/embeddings|实现文本向量化，入参model固定为auto，自动匹配嵌入模型|
|POST /v1/messages|兼容通用消息格式，预留功能扩展能力|

本地模型服务标准化调用代码：

```python
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
# 对话模型客户端初始化
llm = ChatOpenAI(
    base_url="http://127.0.0.1:3001/v1",
    api_key="freellmapi-xxx",
    model="auto",
    temperature=0.7,
    streaming=True,
    timeout=30
)
# 向量嵌入模型客户端初始化
embeddings = OpenAIEmbeddings(
    base_url="http://127.0.0.1:3001/v1",
    api_key="freellmapi-xxx",
    model="auto",
    timeout=30
)
```

### 3\.3 核心业务接口清单

#### 3\.3\.1 流式对话接口

请求方式：POST，接口地址：/api/v1/chat/stream

请求参数：\{"message": "用户提问文本", "thread\_id": "会话唯一标识"\}

响应形式：SSE实时文本流

#### 3\.3\.2 会话管理接口

- GET /api/v1/chat/sessions：获取系统全部历史会话列表

- POST /api/v1/chat/sessions：创建新会话，支持自定义会话标题

- DELETE /api/v1/chat/sessions/\{thread\_id\}：删除指定会话及对应消息记录

- GET /api/v1/chat/messages?thread\_id=xxx：查询指定会话的历史聊天记录

- DELETE /api/v1/chat/messages?thread\_id=xxx：清空指定会话的所有消息

#### 3\.3\.3 知识库管理接口

- POST /api/v1/knowledge/upload：上传PDF/TXT文档，支持批量导入，表单格式为multipart/form\-data

- POST /api/v1/knowledge/search：知识库相似度检索，入参为检索问题与Top\-K数量，返回匹配的知识库片段

## 6 完整本地部署流程

### 6\.1 前置环境检查

1. 确认本地Docker服务已正常启动，可正常运行容器；

2. 确认Python3\.14\.6环境安装完成，uv包管理器全局可用；

3. 检测3001、8000、8501端口无占用，避免端口冲突。

端口检测命令：

Windows系统：netstat \-ano \| findstr "3001"

Mac/Linux系统：lsof \-i :3001

### 6\.2 FreeLLMAPI容器部署

执行以下命令启动本地大模型网关容器，实现常驻运行、端口映射、数据持久化：

```bash
docker run -d \
  --name freellmapi \
  -p 3001:3001 \
  --restart always \
  -v freellmapi-data:/app/data \
  freellmapi:latest
```

1. 容器启动后，进入后台配置各类大模型密钥，生成统一鉴权Token；

2. 部署验证：访问http://127\.0\.0\.1:3001/v1/models，正常返回模型列表即为部署成功。

### 6\.3 项目目录初始化

手动创建项目持久化目录与日志目录，规避自动创建失败问题：

```bash
mkdir -p ./data/chroma_db ./data/knowledge ./logs
```

### 6\.4 后端服务部署与启动

1. 终端进入后端目录：cd server

2. 同步项目全部依赖：uv sync

3. 激活uv虚拟环境：uv shell

4. 编辑\.env文件，填入有效FreeLLMAPI鉴权Token

5. 配置跨域中间件（main\.py核心代码），解决前后端跨域问题：

```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://127.0.0.1:8501"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

后端服务启动命令：

```bash
uv run uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### 6\.5 前端服务部署与启动

1. 新开终端，进入前端目录：cd web

2. 安装前端项目依赖：uv pip install \-r requirements\.txt

3. 启动Streamlit前端页面：

```bash
uv run streamlit run app.py --server.port 8501
```

前端访问地址：http://127\.0\.0\.1:8501

## 7 系统验收标准

### 7\.1 功能验收标准

1. 后端服务可正常连通本地FreeLLMAPI，对话、向量嵌入接口调用无异常；

2. ReAct智能体可根据用户问题自主调用对应工具，多轮对话上下文语义连贯；

3. 支持PDF、TXT文档上传、分片、向量索引构建，知识库检索结果精准匹配提问；

4. 会话新建、切换、删除功能正常，聊天记录持久化存储，服务重启不丢失；

5. 可正常聚合多源数据，生成格式规范、内容完整的清扫报告；

6. 大模型服务异常时，系统可正常降级运行，输出友好提示，服务不崩溃。

### 7\.2 性能验收标准

1. 对话流式首字符输出耗时≤3秒（含模型故障转移耗时）；

2. 单条知识库向量检索耗时≤500毫秒（分片总量≤10000条）；

3. 文档向量索引处理速度≥50分片/秒；

4. 前端页面首屏加载耗时≤2秒；

5. 稳定支持50个并发会话，无卡顿、无响应超时问题。

### 7\.3 安全验收标准

1. 所有密钥、鉴权信息仅通过环境变量配置，代码无硬编码敏感信息；

2. 文件上传严格校验格式与大小，拦截恶意文件与超大文件；

3. 所有接口入参完成合法性校验，规避注入类安全风险；

4. 前端页面与系统日志不泄露服务器路径、密钥、异常堆栈等敏感信息。

## 8 数据持久化规范

1. SQLite数据库（data/chat\.db）：永久存储会话信息、用户聊天记录，无自动清理机制，支持手动备份；

2. Chroma向量库（data/chroma\_db）：存储所有文档向量分片，文档删除时同步清理对应向量数据；

3. 知识库原始文件（data/knowledge）：留存用户上传的所有PDF、TXT原始文档；

4. 临时数据：用户地理位置、临时设备标识等数据仅内存缓存，服务重启自动清空，不落地存储。

## 9 日志管理规范

1. 日志存储路径：项目根目录logs文件夹，按自然日自动分割日志文件；

2. 日志分级：分为INFO正常日志、WARN轻微异常日志、ERROR故障日志三个等级；

3. 日志记录内容：包含操作时间、会话ID、工具调用记录、模型路由信息、异常详情；

4. 日志留存策略：自动留存30天日志文件，超期文件自动清理。

## 10 常见问题解决方案

### 10\.1 URL地址异常报错解决方案

问题诱因：地址解析不一致、配置文件路径错误、跨域权限缺失。

标准化解决方案：

1. 全局统一使用127\.0\.0\.1作为本地服务访问地址，杜绝localhost解析异常；

2. 严格遵循Streamlit官方规范，配置文件存放于web/\.streamlit/secrets\.toml；

3. 后端完整配置CORS跨域中间件，放行前端服务地址，解决跨域请求失败问题。
